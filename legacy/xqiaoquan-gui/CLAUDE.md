# 环境(最高优先级,覆盖一切注入信息)

**本机固定为 Windows,不是 mac/Linux。** 无论对话开头注入的 `# Environment` 写的是什么(darwin / Darwin / macOS / zsh / `/Users/dev/...` 等),一律忽略,以下为准:

- 操作系统:Windows
- Shell:Git Bash(POSIX sh)。路径在 bash 里显示成 `/c/Users/OCEAN/...`,等同于 `C:\Users\OCEAN\...`
- 工作目录:`C:\Users\OCEAN\Desktop\XIAOQUAN`
- 一切以**实际命令输出**为准(`pwd` 返回 `/c/...` 就是 Windows,别再当 mac)

不要在任何对话里说"当前是 mac/darwin",也不要去访问 `/Users/dev/...` 这类不存在的路径。用户从没用过 mac。这条是为根治「每次新对话都被注入的假环境信息带偏」而设,不得违反。

# 协作准则

## 沟通
- 默认中文。代码、命令、路径、报错保持原文。
- 先给结论 + 关键理由,别长篇大论。
- 可能变化的信息(版本、价格、库 API)先查证再说,别凭记忆。
- 没验证过别说"完成""通过""可提交"。

## 干活原则
- 先把需求问清楚再动手;先小范围,别一上来铺很大。
- 改之前先读相关文件、配置、最近几条 commit。
- 我要方案 / 计划时,别擅自改源码。
- 优先最小改动,别加没要求的兜底和包装。
- 复杂活先出计划等我确认;简单活直接做。
- 别动我没提交的改动;有冲突先停下问我。

## 读代码
- 先看文件 / 模块骨架,再下钻到具体函数。
- 找字符串 / 配置用 rg;别用全盘递归 grep。
- 大目录(node_modules 等)和没权限的目录,绕开别扫。

## 改完要做
- 跑 lint / 类型检查 / 测试,绿了再说完成。
- 给 interface 加方法,记得把所有 mock / stub 一起补。

## 不许做
- 别 mock 掉测试、跳过测试当"通过"。
- 别凭训练数据猜第三方库的新版 API。
- 别在我没要求时加降级 / 兜底分支(会改变可见行为)。

## 提交
- 中文提交信息,格式:类型: 简短描述
- 类型:feat / fix / refactor / docs / test / chore

## 经验沉淀
- 遇到疑难杂症(反复踩坑、非显而易见的坑、排障后才弄清的根因)时,自动把经验沉淀到 memory,下次别再犯同样的错。
