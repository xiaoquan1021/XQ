# XQ synthetic DICOM fixtures

These files are fully synthetic technical test data generated by
`tools/generate_dicom_test_fixture.cpp` with the official GDCM library. They
contain no patient, institution, accession, operator, study-description,
series-description, protocol-name, private-tag, or burned-in identifying
values. GDCM-required Type-2 patient/accession tags may be present with zero
length; `test_dicom_fixture_policy` enforces that they remain empty.

The fixture set is intentionally tiny:

- `regular-oblique`: 4-slice CT, 4x3 pixels, non-identity LPS direction,
  0.7x0.8x1.5 mm spacing, stored values with slope 2 and intercept -1024.
- `multi-series`: two explicit SeriesInstanceUID values in one directory (CT
  and MR) with distinct dimensions and sentinel scalar values.
- `non-uniform`: negative fixture with slice gaps 1 mm then 2 mm.
- `mixed-orientation`: negative fixture whose second slice changes IOP.
- `invalid`: one fixed non-DICOM sentinel used to verify structured failure.

All valid instances use fixed synthetic UIDs, `StudyDate=20000101` and
`StudyTime=000000`; regenerating twice produces byte-identical files.

CTest reads these committed files but never generates or modifies them. To
rebuild them deliberately, build the excluded target `xq_generate_dicom_fixture`
and run it with this directory as its sole argument, then rerun the fixture
policy and adapter tests before accepting any byte changes.
